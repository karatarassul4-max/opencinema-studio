# OpenCinema Studio v2 release validation

Release review date: 2026-11-04. Based on published main commit `3a9c4d1` and selected source from `D:\comguopensource-v2`. Prepared in an independent checkout so the live demo and legacy v1 remain unchanged. No deployment or automatic merge is included.

## Changes from the published application

- Modular v2 Director, duration selection, benchmarking, optional telemetry and HD export implementation.
- Existing v2 interface preserved: scene/mood/camera/strength/seed controls, final prompt preview, video playback/download, history and HD actions.
- Four duration options (25/49/73/97 frames), up to 4.04 seconds nominal; distinct 97-frame six-step experiment.
- Separate HD graph generated by app/hd_export.py; output ownership and metadata validation, persisted status, completed-export reuse and retry behavior.
- Offline inference default, project-local storage, private-demo authentication settings and recovery safeguards.
- Current English README, architecture guide, current offline UI screenshot and updated attribution.
- Repository ignores for secrets, databases, outputs, weights, environments and backups. Obsolete v1 workstation launch/config helpers removed from the current tree; history, licenses, older workflows and explicitly marked historical documentation retained.

## Narrow release fixes

The source's late HD button reassignment already addressed part of the refresh problem. The release makes active-state calculation happen before initial button state, honors inference gating, and rejects stale asynchronous HD responses. Offline tests assert enablement immediately at completion before the lookup resolves; no GPU pipeline change.

A 73-frame backend label claimed tested status while the frontend and available evidence warned otherwise. The release conservatively labels it unverified experimental. The 73/97-frame workflows are retained unchanged. Editor titles in the 97-frame graph differ from the baseline, but executable inputs are equivalent apart from duration; tests compare executable content rather than editor labels.

## Validation

- **215 pytest tests passed** on Python 3.11.9 / Windows using existing pinned direct dependencies. No dependency installation or upgrade was performed.
- One upstream Starlette/AnyIO BlockingPortal deprecation warning; no failed tests.
- Node 22.20.0 offline DOM harness passed: four durations, 97-frame six-step form selection, Director preview, performance labels, HD immediate completion state, retry state, stale-response handling and inference gating.
- Mocked HD tests cover ffprobe constraints, expected graph parameters, ownership/path rejection, full completion and download, duplicate export reuse, and rejection of mismatched output dimensions.
- Network sockets blocked by the pytest harness; inference and live GPU monitoring disabled. No ComfyUI/FastAPI service started or stopped; no generation, model load or hardware stress test.
- Python AST checks passed for 16 files; JavaScript syntax checks passed for the application and DOM harness. All 15 tracked JSON files parsed; 156 API-workflow node links resolved, and 13 local links in current documentation resolved. Staged-file scans found no prohibited runtime artifacts or recognized token/private-key/URL credential patterns. Pattern scans do not guarantee absence of every possible secret.

Initial copied-tree test results exposed portable-test setup issues, not live application regressions: default pytest temp directories violated the project-local storage rule; two tests required unpublished backup snapshots; the DOM stub lacked APIs used by the newer UI. Fixed test setup uses isolated per-test data inside ignored artifacts/offline-tests, checked-in sanitized evidence hashes and a current DOM stub. No backup directory or live database was published. Added 97-frame coverage revealed only editor-title differences, with no executable-input changes.

## Evidence limits and remaining work

No new GPU measurements, model compatibility claims or output-quality results were generated during release preparation. Earlier 25/49-frame timings remain explicitly manual observations. 73/97-frame memory viability, the six-step quality tradeoff and HD quality/performance are not established by mocks. The final Cinematic Smoke Reveal recording URL is still pending. The screenshot shows the real UI with mocked offline data, not a generated result.

The optional public-demo mode needs an independently managed HTTPS boundary and private runtime credentials. No secret values or public deployment configuration are included. Full multi-tenant hosting, cancellation and automatic retention are outside this release.

## Provenance

V2 runtime source and all six local workflow JSON files were copied selectively; installers/patch scripts, backups, LTX2.5 lab research, private runtime artifacts and machine configuration were excluded. Existing upstream MIT notice and historical credits remain. config/phase3-verification.json preserves earlier workflow/director hashes; config/ltx-frame-constraints-evidence.json retains the constraint snapshot with personal absolute paths replaced by Comfy-relative paths. It is historical metadata evidence, not a live-node guarantee on another machine.
